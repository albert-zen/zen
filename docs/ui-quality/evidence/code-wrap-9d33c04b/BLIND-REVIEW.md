### 评分证据

**M 未换行状态：**三条长代码的右侧都被容器截断。开头和缩进可见，但无法在同一视野读完英文句子、中文说明或连续 token。代码区紧凑，下面的解释与输入框保持清晰独立。只有 Copy 文字，当前图没有提供解除长行阅读负担的显式选项。

**M 横向滚动状态：**出现滚动条，能看见中段文本，溢出机制更明确；代价是左侧变量名、缩进和英文句首消失，依然不能同时对照首尾。滚动条证明该画面处在横向位移状态，不证明完整滚动范围或操作质量。

**N 未换行与横向滚动：**长行本身的显示问题与 M 基本相同，所以不因新增按钮而抬高文本可读性分数。Copy 与 Wrap lines 并列在代码栏右侧，含义比纯图标直接，新增发现路径所占空间很小。未激活时文字偏弱、字号偏小，仍容易被当作次要元信息。

**N wrapped：**英文句末、中文末尾以及连续 token 的结尾均进入视野，长文本阅读的主要收益真实可见。代码块从约 160px 增至约 307px 高，解释下移约 147px；此样例中输入区位置不变，也没有遮挡正文。三条逻辑代码变成更多视觉行，没有行号或续行标记；连续 token 被从词中间折断，续行回到左缘，与原始缩进不易区分。因此适合读内容，不等于最佳代码结构审阅模式。

**N copied：**Copy 位置出现 Copied，局部结果反馈清楚，且不另弹出大面板。按钮周围方形细框与 Wrap lines 的圆角/底色表现不完全统一。静态图无法判断它是焦点框、点击状态还是其他样式，不能直接判为错误。

**N unwrapped-restored：**代码区恢复紧凑和右侧截断，说明截图组包含两种不同的呈现；不能仅凭文件名认定状态机正确。图中 Copied 仍在，Wrap lines 有外框，二者视觉状态可见，但恢复动作是否重置横向位置、反馈持续多久都不可知。

**N wrap-keyboard-focus：**实际图像中的 Wrap lines 没有足够醒目、可独立识别的焦点外观，整体接近横向滚动画面。文件名不是键盘可访问性的证据，故不因名称而额外加分。需另行真实键盘验证。

**共同外壳：**标题、解释、代码、后续说明、输入区左缘一致，导航与对话分区稳定。深浅主题都保持布局与语义一致，没有明显挤压或溢出。主标题突出，代码不抢夺导航空间。缺点是侧栏 Projects 与 Recent 重复出现同一 Thread one，空项目提示较多；正文与输入框之间空白偏大，输入区下方多项弱对比标签与小图标的理解成本较高。深色代码边界和弱文字较暗；浅色代码底色与正文区差异不强，但没有足够证据给两个主题不同的分数。

N 的 wrapped/copied/restored 图还出现时间和消息动作行，其他部分截图没有。这是可见差异，不应归因为换行控制；不拿它证明某项交互的结果。

## 收益、代价与保留建议

**结论：值得保留 N 中的可选 Wrap lines 控制，同时保留未换行和横向阅读路径。**理由不是 N 的名称或推测的新旧关系，而是图中完整文本确实变得可见，新增控制只占一个短标签位置，未破坏主对话结构。M 更简洁，但这种简洁让阅读长行的成本转嫁给横向滚动。

主要收益：
1. 中英文长句不必横向来回寻找句尾，正文和后续解释能一起阅读。
2. 连续无空格 token 也未突破容器，避免拉宽整个对话。
3. Copy 与展示选项处于代码本地，作用域容易理解；Copied 提供直接、低干扰反馈。

主要代价：
1. 样例代码块高度接近翻倍；更长真实代码可能让后续解释退出首屏，本截图不能覆盖该情况。
2. 视觉换行与源代码行界不明确，连续 token 的断点尤其降低结构扫描效率。
3. Wrap lines 激活后仍使用同一文案，开启状态依赖底色/外框；这些表现又可能与焦点混淆。最好让“已开启”与键盘焦点使用不同的视觉语言，而不是仅堆叠边框。
4. 控制字小、对比偏弱。提升命中区域和可见性时应保持代码头栏克制，不必增加常驻大工具栏。

优先改进建议：明确的开关状态表达；可独立识别的键盘焦点；温和的续行标记或缩进策略；保持 Copy 与换行控制的外观语言一致。是否默认开启换行不能由这一组三行合成代码决定，需要真实长代码、嵌套缩进及窄窗口任务验证。

## 证据边界

本次没有操作界面、没有检查源码、没有运行测试、没有读取剪贴板。截图不能验证：点击/键盘切换是否正确、焦点顺序、屏幕阅读器语义、Copy 是否复制原始未换行内容、中文标点和空格是否保真、连续 token 是否完整、滚动恢复位置、反馈超时、多代码块独立性、移动端或窄窗口适配。画面中关于复制源代码的说明及 Copied 标签是界面宣称，不是剪贴板正确性的证据。
