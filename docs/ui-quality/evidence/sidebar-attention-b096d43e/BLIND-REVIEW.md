# 独立图片盲评：A / B 注意状态与浮层

## 范围及证据纪律

逐张实看 A、B 各 6 张 PNG，并实看指定的 T3、Codex、Claude、DSH 四张参考图。未查源码、提交、历史或实现说明；不知道 A/B 的新旧顺序。只评当前静态可见结果，不把文件名 escape、cleared、dock-closed 当作按键、清除、关闭已成功的证据。不测试也不宣称交互通过。以下分数是视觉评审刻度，不是测量值，0.5 分差只表示小幅倾向。不同内容量、视口和任务的参考图不参与产品排名。

## 总结

**有注意徽标且行尾有省略号的四组场景，窄幅偏好 B；cleared 两组平局。** B 的实际收益非常具体：左侧 Design review 行的“待回答 / Asking”能完整呈现，并与行尾省略号并存；A 同一行徽标后半部分被渐隐/遮盖，看起来像残缺内容。代价也真实：B 把线程名称截得更早，Design review 后的中文描述几乎完全消失。B 不是主对话或全局布局的大幅改善，不能凭此声称整体系统已解决。

若任务优先级是找出需要回答的线程，B 的小幅净收益成立；若优先级是同时区分多个 Design review 同名前缀线程，则这个截名代价需要另行验证，不能无条件推广。两套的浮层都遮正文、主栏和右栏分隔偏弱、长名称/状态密度问题仍在。不要扩大为跨任务排名。

## 每场景偏好、证据与代价

### dark-overlay-escape：B 小胜

A 的 Design review 行右侧待回答徽标只剩部分文字/底色，旁边省略号仍明显。B 徽标完整，“名称 → 徽标 → 更多操作”更像三个明确区域。B 名称只保留英文前缀及截断符，少了 A 可见的一小段中文。主正文在 A/B 间有约一行内的纵向偏移，B 可见滚动条，不能据此推断锚点保持或滚动退化；这是待交互验证的差异，不计为 B 阅读改进。

### light-overlay-escape：B 小胜

同样是 B 完整呈现 Asking，A 在当前行呈现残缺的 Ask…/淡出效果。浅色徽标文字和底色仍偏淡，B 修复完整性而非彻底修复对比度。名称截断代价同上。右侧的 Idle / Working 与 Asking 是并列的两种状态，但未说明谁应回答；不能从完整标签进一步推断语义已无歧义。

### dark-overlay-dock-closed：B 小胜

主区宽度、输入区及浮层位置基本相同，没有主对话净收益。B 的完整待回答徽标与省略号更可扫读。浮层给出完整 Design review 名称，当前帧略微缓和截名代价，但不能假设所有用户都会触发浮层或能用键盘访问。两者浮层都盖住编号列表及正文片段，读文代价相同。右栏不可见，不评关闭行为及右栏体验。

### light-overlay-dock-closed：B 小胜

B 完整 Asking，比 A 淡出缺字可靠。名称更短、浅色徽标对比不足仍是成本。浮层有较明确的阴影和边界，但盖住正文；不把阴影更可见等同于交互更好。

### dark-cleared：平局

无待回答徽标时，两者名称、选中项、右栏、浮层和主文排布视觉上无实质差异。加载环朝向等瞬时差异不是设计优势。浮层标题可读，字段值相对暗，正文仍受遮挡。没有足够证据支持选 A 或 B。

### light-cleared：平局

同上，无实质净收益，不接受把该场景作为 B 改进的证据。名称空间较有徽标时更充足，但这是同一场景共同特点。

## 整体体验的共同问题

1. 主对话正文大小和行距可读，标题层级清楚。展开右栏时正文约 600px 的宽度较舒服；右栏隐藏时正文更长，不能简单认定越宽越好。
2. 左侧 Projects 和 Recent 重复出现相同线程，注意徽标也重复出现；可用但提高扫描成本。当前 Thread one 在两处的选中背景强度不同，尚有解释成本。
3. 右栏长 Implementation 名称换行后再放 Working/Asking，行高与短项不同；名称和 Shown 操作能区分，但主栏与右栏边界偏弱，整区像浮在同一画布上。
4. 行尾省略号是合理的更多操作线索，B 在关注行中为它和徽标留出的视觉分区更成功；不能证明点击热区无重叠。
5. 深色普通文本对比更明确，浅色标签偏淡。大量 Local demo/本地演示、Idle/空闲等次要文本虽能读，却与状态争夺狭窄行宽。
6. 浮层信息较克制、标题完整，但“最近消息不可用”等占据显著面积，当前截图的阅读回报有限。此意见仅基于提供的内容，不推断真实数据能力。

### T3

主内容用 Done、代码框、表格组织，完成结果的层级清楚，正文与输入区关系稳定。左侧一条主要线程名称可读，但样本量很小，不足以评价长列表复杂状态。背景网格比产品信息更装饰性。顶栏和代码框操作偏小且依赖图标。没有右栏、没有待回答状态，所以不能拿它证明复杂注意状态方案优劣。

### Codex

主文、文件链接与正文有明显层级；左侧分组与行距统一，名称空间较多，时间和时钟图标占独立的右端区域。可借鉴的是列分工，而不是机械增加宽度。顶部标题仍有截断。Review work context 前有圆环，但截图不能确认它是待回答、运行中还是其他状态，注意项 N/O。右栏未展示。

### Claude

实看的是官网中嵌入的产品演示，不是全屏应用，缩放和页面框架影响了观感，分数须保守解释。主区代码差异、文件变更和总结分层清楚；左栏多个长任务名消失于右缘，名称完整性明显有限。蓝点和 CI 绿点可见，但不足以判断待回答状态，注意项 N/O。文案称 preview 在右边，图中未展示，不能据此评分右栏。

### DSH

主对话、用户气泡、完成状态、任务摘要和输入框分区明确。顶部子智能体列表浮层可读，两项名称及次级标识组织清楚，但覆盖上部内容。左侧当前名称截断；“任务 2 已完成 · 1 进行中”清楚表达进度，不是用户待回答证据，因此注意项 N/O。顶部浮层不是完整右栏，右栏仍 N/O。

## 需要后续验证，而非本次已通过

- Esc 是否关闭正确浮层，焦点是否返回、阅读锚点是否保持。
- 徽标、名称和更多操作的热区是否分离，键盘与屏幕阅读器能否访问。
- 多个同名前缀长线程在 B 中能否无额外困难地区分。
- 浅色徽标实际对比度，窄视口、缩放及更长本地化文案。
- cleared 是否真实清除了注意状态，是否在所有入口同步。

**决策建议：仅认可 B 在带徽标且带行尾操作的四张截图中的小幅修正；cleared 拒绝宣称收益。无需为此更换整套布局，也不应据这些静态图片作交互验收或跨产品胜负判断。**
