# 桌面主对话阅读节奏盲评

## 方法与结论

实际用 view_image 查看全部 20 张原始全幅图：X、Y 各 8 张及 references 四张。没有读取源码、其他报告或历史；不判断版本先后。评分只针对这些静态画面，不是产品总分。0–10 越高越好；注意力指主任务聚焦程度，可发现性指画面中控件与状态能否被理解。半分级主观判断，0.5 分差不应理解为统计显著。

**总体轻微偏好 X，但不是全面胜出。** X 在正文仍有足够呼吸空间的前提下，让相邻论点、列表和代码后的解释更容易同屏看见。Y 的行间呼吸更松，单段逐行阅读略舒服，尤其宽栏长英文；代价是同一阅读窗口里更快失去后续上下文。两者导航、控件与整体布局基本无差异，不能说 X 已经解决整体界面问题。若任务是连续慢读而非来回对照，Y 完全合理。

## 可见差异与代价

- 主标题位置、内容列宽、左栏、顶栏、输入区大小和位置基本一致。最明显差别是 Y 正文、列表和代码行节奏较松，内容向下累计位移；并不是一次明显的布局重构。
- 长文顶部：X 能完整露出两个嵌套列表项，Y 只露出第一个。两者都完整呈现主标题与几个段落，X 没有为密度牺牲标题识别；Y 的单段更舒展，但这属于阅读节奏取舍。
- 标题列表：X 的后续代码卡顶缘可见，Y 仍停在代码引导文字附近。X 把列表、表格及下一节关系放在同屏；Y 的列表分隔更轻松，但纵向消耗较多。
- 表与代码：两者的表格、说明、代码均完整可见。Y 的代码区略高，下面解释和引用更靠近输入区。X 的引用有更充分的露出空间。两者顶部标题都紧贴顶栏截断边缘，这一截图状态本身不够舒服。
- 资料打开：实际看到的是 Subagents 两行状态，不是信息丰富的资料卡。两者右栏均占用明显宽度而内容很少。X 还露出正文第一条列表，Y 刚完成第三段。右栏开启让英文行长更适中，但也令主对话从约 800px 收窄至约 590px，阅读窗纵向成本上升。X 只是缓解，没解决空右栏与正文挤压的失衡。
- 浅深模式中的相对差异一致。深色模式正文对比鲜明，导航次级标签和代码语言/复制控件较暗；浅色导航大面积灰底略重，但正文仍是第一注意对象。

## 共同问题与建议

1. 输入框在宽栏图中边框比代码卡、表格和页面边界更抢眼，固定占据底部约百像素。能快速找到回复入口，但长文阅读总是在一个醒目的水平边界处中断。建议优先验证滚动时的遮挡、焦点态与渐隐处理，而不是继续压行距。
2. 左栏同一 Thread one 同时出现在项目和 Recent，两块选中/近似选中背景容易产生重复焦点。大量空项目行占据持续的视野面积，正文较长时左栏提供的有效上下文偏少。
3. 右栏 Subagents 的 Idle、Hidden 与 Hide 并列，文字相近而语义关系不够清楚。仅凭图不知道 Hidden 是状态还是操作；在没有右栏需求时，开着这块区域代价较大。
4. 宽栏英文一行较长，Y 增加行间距有真实价值，不应简单判为浪费。若保留 X 的总体节奏，应在更长文章、更多嵌套列表、窄屏及中文中验证眼动和段落连续性，避免全局压缩。
5. 顶栏只有 Thread one 和工作路径，长文标题不跟随，截图滚到中段时缺乏文章级定位；两版相同。标题/列表与表代码截图顶部都有内容紧贴固定顶栏的现象，需实际滚动确认是否只是选定截图位置。

- **Claude**：为网页内产品展示，外层营销导航不等于产品导航。产品内部把编辑结果、命令、结论及分支/CI上下文连续串联，输入入口纤薄；较浅的小字号灰文字和横向代码滚动降低截图可读性。可借鉴结果到下一步的层级，不直接照抄密度。
- **Codex**：问题气泡、历史折叠、答复、产物与风险提醒同屏，答复是主要视觉对象。输入框轻且与正文间有明显留白，侧栏内容密集但分组明确。顶部空白较多，短回答状态的舒适不等于长文时也高效。
- **DSH**：任务完成标题与关键链接突出，底部任务条把进展与输入衔接起来，功能文字比纯图标更易发现。顶部子智能体块、问题气泡、任务条与输入四种面板会争夺注意力，长文下未必更安静。
- **T3**：中央内容连续，代码与表格宽度一致，输入框低调。左栏装饰网格、较暗的辅助文案及多个无标签小图标削弱阅读纯净性或可发现性；正文下方大留白是这张短回复的状态，不应转化为长文布局结论。
- **Linear**：未提供图，N/O，不排名、不补猜。

## 未验证范围

没有操作任何界面。未验滚动锚定、键盘与焦点、悬停/工具提示、复制、发送、资料开关、子智能体状态、响应式、缩放、无障碍对比度数值和屏幕阅读器。X/Y 未展示中文正文、真实长对话、多轮边界、真实资料内容或极端表格代码；DSH 参考含中文界面标签不能替代这些测试。也未测用户阅读速度或长期疲劳。因此建议属于静态视觉取舍，不是交互验收或可用性实验结论。
