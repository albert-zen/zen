# P / Q 桌面截图独立盲评

## 范围与方法

实看 P、Q 各四张原尺寸截图（light/en 与 dark/zh，各 pending、cleared），以及指定的 T3、Codex、Claude、DSH 四张参考原图。未查源码、产品历史、实现说明或新旧映射，未预设目标分。以下仅是静态视觉评审，不证明点击、键盘、状态更新、滚动保持或任何行为测试通过。分数为 10 分制主观判断，0.5 分只是表达相对差距，不是统计精度。

六列含义：①需处理事项发现性；②活动状态与注意事项区分；③名称可读性；④三栏一致性/层级；⑤空间利用；⑥本截图整体偏好。cleared 的①评估“没有额外待回答提示”的可辨识性，而非假设已验证问题真正解决。参考图没有同任务/结构的可核验证据时标 N/O；不以跨产品平均分排名。

### 可定位的观察

- **pending 的实质差异在右栏，不是徽标数量本身。** P 左栏 Design review 和 Implementation 有 Asking/待回答提示，右栏同名条目只显示 Idle/空闲或 Working/正在工作。阅读右侧子会话清单时，“空闲”很容易被读成“不需要我处理”。Q 在这两个右栏条目的活动状态旁另列 Asking/待回答，空闲和待回答可以同时成立，工作中和待回答也可以同时成立。这是可解释的信息增量，因此①②上升。
- **Q 没有改善左栏的截断。** 两组 pending 的左侧 Implementation、Design review 名称都受徽标、旋转形符号/更多按钮及窄栏挤压；项目区和最近区重复出现，使提示重复但名称仍不全。Q 右侧名称与状态分行，名字没有新增显著截断，但长的 Implementation 名称仍换行。“更多徽标=更好”不成立，③不给加分。
- **右栏代价是高度和对齐。** Q pending 中 Design review 增加第二行，Implementation 的状态行仍在较长名称下方，后续 Test coverage、Unavailable review 被向下推。密度下降；有待回答的条目与无待回答条目采用不同布局，扫描同一“活动状态列”更不规则。现有四行内容尚无拥挤危机，但不能推断二十行仍良好，⑤扣 0.5。
- **两组 cleared 视觉结果基本相同。** 左右待回答提示均不再出现，右侧仅保留活动状态；名字在左栏获得更多空间。Q 没有留下空徽标占位或额外永久行高的明显证据。不能因为 Q pending 信息更多，就给 cleared 同样加分。
- **明暗主题收益方向一致。** 浅色 Asking 用淡蓝底/蓝字，暗色待回答用深蓝底/浅蓝字，均与中性活动状态可区分。但两者都较小，不是强警报；如需极快定位，还有提升余地。暗色侧栏次级字、图标及 composer 控件偏暗，这是共有问题。
- **三栏已有基本秩序，但不精致。** 左侧导航、中间正文、右侧子会话可区分，正文层级清晰。右栏小字号和宽松空白、左侧重复列表/元数据、中间较大正文的密度差仍明显。Q 补齐左右对同一待回答事实的表达，只小幅提高一致性，不等于整个三栏质量大幅提升。
- **截图存在共同遮挡条件。** 聚焦的 Design review 资料 popover 覆盖正文左半部分，两组都有；本评审只评价这一已呈现状态。不能以此宣称正常阅读始终被挡，也不能推断关闭 popover 后的全局效果。Q dark 两张的正文相对 P 向下约一行，能看到略不同的段落切片；这可能是采集位置差异，截图不能归因于布局改动或滚动回归，因此未据此奖惩。

## 结论与建议

**在待回答场景，我偏好 Q；在 cleared 场景，P/Q 持平。** Q 的净收益是让右栏成为可信的待回答入口，并把活动态与需人处理态拆开表达，消除“空闲却实际等回答”的局部歧义；代价是右栏增高和状态扫描位置不统一。收益是针对特定任务的实质修补，不支持“整体产品已经全面胜过参考界面”的结论。

优先保留这种语义拆分，而不是继续增加徽标：下一步可比较右栏统一的名称行 + 状态行，或统一状态位置，确保名称优先且无问题时不留下多余空洞。左侧重复列表、名称截断、低对比次级文字是两组共有的后续问题。本次没有操作验证、没有修改或发布。
