# A/B 桌面密度独立盲评

## 方法与结论

只读取本目录列出的 12 张图片，以 `view_image` 实际打开全部完整原图，没有查看源码、其他目录、版本历史或版本先后信息，也没有只用裁剪作判断。产品图为所提供的 1280×900 全幅桌面。以下是静态视觉判断，分数为主观诊断刻度，不是测量结果。

**短英文名称场景：B 小幅胜出于名称/状态层级和跨长度一致性；A 胜于紧凑扫描。长名称场景：A/B 肉眼未见有意义差异。主对话和左侧栏四组配对均无可见改善。若必须选择一套统一规则，我轻微偏向 B，但这不是全界面的显著胜出。**

B 将短名称下的 Idle 独立成行，让状态不再接在名称尾部，和长名称卡的语法一致。代价是两项资料卡列表从约 36px 的行间步长增为约 54px，第二项整体下移。当前仅两项、右侧大量空白，代价小；项目很多时会减少一屏可见数量。因此不能把 B 简单称为“密度更优”。

## 场景观察

### 1. 浅色 / 短英文名称（information-reading）

- 中央正文标题、段落行距、输入区和左栏在 A/B 中视觉相同。阅读主区域不受右栏调整挤压；正文仍是最强视觉锚点。
- A 中 `Design review Idle` 和 `Test coverage Idle` 同排，Idle 虽然更灰，但名称与状态之间留白很小，容易把状态读成名称延续。优势是两项快速纵向扫描、更紧凑。
- B 中名称独占一行，Idle 在下方左对齐，属性关系更明确。两条状态都更容易定位，但每项的图标、名称、Hidden 仍以第一行为主，不应误称整张卡都居中重排。
- `Hidden` 文字和图标一直可见，可发现性主要未变。把 Idle 换行不是新增入口。右栏齿轮、编辑图标等无文字的入口仍需熟悉或悬停才知语义。
- 左侧项目/最近重复显示当前会话，选中底色区分明确，但空项目提示占了不少空间。A/B 都没有解决这项密度开销。

### 2. 深色 / 短英文名称

- 布局结论同浅色。正文对比强、主次分区清楚；黑色左栏与深灰主区域分离明显。
- 灰色辅助标签、底部控制与线性小图标在深色下更弱，不如正文容易读到。这是两套共同问题，不是 B 的换行能完全补救。
- B 提升状态归属关系；A 保持更紧凑的目录节奏。单凭本图无法证明哪种点击或键盘操作更快。

### 3. 浅色 / 长英文与长中文名称（supporting-rails-long）

- A/B 未见有意义差异：英文资料卡名称都换为三行左右，中文名称也自然换成多行，Idle 均另起一行；两套都没有把完整名称挤成单行省略号。
- 资料卡标题完整性较好，但大段细小多行名称会消耗高度；状态与名称至少有独立行，不与正文争抢字号。
- 左侧项目名、会话名出现截断，特别是重复的长会话名只能看到近似前缀。中间顶部标题提供完整英文内容作为补偿，但不能证明其它未选中会话也有同等补偿。列表中区分前缀相同的多个项目会有风险。
- 中文资料卡换行可以辨认，没有明显溢出或覆盖；但没有短中文名称样本，也没有更多极端字符/混排样本。不能宣称所有中英文长度均通过。
- 下方 Thread triggers 分组与细分隔线容易发现；名称与右侧开关/编辑控件保持分列。英文触发器占两行、中文触发器较紧凑，是内容长度造成的节奏差异，A/B 一样。
- 主阅读区域未变。右栏信息多了，但标题仍居中部主导，辅助面板尚未压过正文。

### 4. 深色 / 长英文与长中文名称

- A/B 同样无可见优劣。多行名称和状态的关系清楚，长名称高度增加是显式的完整信息成本。
- 开关的蓝色状态是右侧最醒目的信号，对发现启用状态有帮助；但相较灰色 Hidden/Idle 也更容易吸引注意力。主正文仍维持首要阅读层级。
- 深色下 Idle、隐藏控制、分隔线偏弱的问题和短名称场景相同。

- **Codex：** 左侧功能与会话分组清楚，行尾时间保持对齐；主回复和底部输入区宽松，文本链接易认。导航和内容各司其职。顶部截断标题与灰色副信息仍要求读者识别关系。不能从这张宽大画面推断 1280px 时同样宽松。
- **Claude：** 导航、变更摘要、代码块和底部 PR 状态层级明确，密度较紧。嵌在网站中的截图整体字小且发灰，长会话在侧栏被淡出，辨认完整名称有成本。官网导航也分散了产品本身的注意力，评分受截图呈现影响。
- **T3：** 回复中标题、代码块、表格有清晰的格式结构，主体内容集中。左侧网格装饰不是信息，增加了一点视觉噪声；工具按钮和输入区附加信息对比较弱，发现性有限。主回复空白充分不等于侧栏能承受大量会话。
- **DSH：** 左栏中文功能入口明确，顶部智能体浮层用名称/副名两行建立关系，和 B 的“名在上、属性在下”有可借鉴的同类语法。对话、时间、任务进度、输入区同时可见，信息充分但竖向层次更多。长会话同样被截断，较低对比辅助文字仍有阅读成本。

## 建议与未验局限

1. 若状态应在每项中稳定可定位，采用 B 的名称/状态二行规则更一致；若真实列表经常有很多短项且密度优先，A 的同行状态仍可成立，但需要明确间隔或更清楚的字段分离，而不是把 Idle 当成名称尾字。
2. 不建议仅凭此图进一步加大正文或卡片间距。主体已经有良好段落节奏，B 的局部高度增长应通过真实长列表验证其代价。
3. 长侧栏名称的辨识问题比这次 Idle 换行更影响导航。可考虑完整名称的可达方式，但本评没有验证 tooltip、键盘焦点或展开行为，也不假定它们不存在。
4. 本次没有验证交互、滚动、悬停、焦点、键盘路径、读屏、可点击范围、状态更新、响应式、实际 CSS 对比度、真实任务成功率或视觉回归像素一致性。没有查看截图以外证据，不声称 A/B 字节相同。
5. 仅有两个短英文资料卡和两个长中英文资料卡。没有短中文名称、超多资料卡、不同缩放或较小窗口样本。桌面截图不能作为完整交互验收。
