## Highest-impact findings

1. **P2 — Empty Rooms landing does not expose its next action.** Target: main empty Rooms page, image 10 after Close (step 10). Pixels say “Create a room to bring your agents into one conversation,” but no actionable create control is visible there; the Rooms header plus is visible on hover in image 08 and used in step 09. A new user must discover an undisclosed hover affordance after reading an instruction that has no adjacent action. Add a labeled control in the empty state wired to the existing New Room action, preserving the section's hover/focus contract; alternatively establish equivalent persistent discoverability without changing navigation. Verify from the empty page with pointer and keyboard and confirm it opens the same form, without auto-creating a Room. This finding is discoverability, not a claim the form is inaccessible.

2. **P2 — Project ownership is visually under-signaled in the populated list.** Target: Projects group, images 01–02; compare the project folder row at x≈17–128 with thread titles beginning at x≈20, and the folder label in muted gray while child titles are darker. The children are not indented under the project; nearby project and thread rows compete as peers even though they have different hierarchy. With multiple projects, users may have to infer ownership from order and expansion. Strengthen the parent/child relationship using a modest indentation or other clear grouping while retaining current row identity, sorting, expand behavior and available title width. Verify with two expanded projects and similarly named threads: a user can identify each owner without opening the detail card. This is a visual association risk, not evidence that data ownership or routing is wrong.

3. **P2 — Long choices are difficult to distinguish in the Room member picker.** Target: image 11, step 11, conversation picker. The first long title is truncated after “keyboard fo…” while its smaller secondary line prioritizes a shortened path and identifier; the form's long Room name also extends beyond the visible single-line input. The picker lets a user see and search choices, but this frame does not expose the distinguishing tail of a long conversation title, which can matter when titles share a prefix. Allow the complete existing title to be inspected by wrapping or a pointer-and-keyboard-accessible detail, and keep project/source context accurate. Verify two fake conversations identical through the current cutoff but different afterward; choose the intended one using pointer and keyboard without trial selection. This frame does not prove that a tooltip, search, or selection never reveals the remainder.

4. **P3 — Keyboard focus outline appears partially clipped.** Target: image 04, step 04, the “File browser and Markdown notes” row after Escape then Tab. Selected long Thread remains filled, and the next row has a fine top/side outline; the lower edge is not clearly visible at screenshot scale. Distinct selection and focus is good, but an incomplete ring is harder to follow against similarly pale rows. Inspect the actual focus rectangle and clipping at native resolution, including first/last visible rows; if clipped, inset the ring or provide a complete high-contrast non-color cue. Verify with Tab in both scroll boundary positions, without changing selection. This is a visible-risk finding, not proof of a keyboard failure or contrast violation.

- **Controlled editing and explicit creation:** images 06–07 plus operator sequence show the original project name restored after Cancel/reopen; image 12 follows explicit Room creation. Preserve Cancel, Save and existing authority boundaries; do not treat a screenshot as proof of durable storage.

### Priority findings for expanded scope

1. **P2 — Two distinct Room identities collapse to the same visible label.** Target images 14–15, steps 14–15: Alpha and Beta differ at the end, but both sidebar rows show the same truncated prefix and “1 member”; the full selected name appears only in the header after switching. This makes deciding which row to open unnecessarily error-prone. Provide the full existing name on pointer and keyboard focus or use a truncation strategy preserving distinguishing suffixes; maintain a visible Room More action and avoid changing identity. Verify with the same two names and two additional identical-prefix names that users can distinguish and navigate before switching. The evidence establishes identical visible labels, not that no tooltip exists for either row.

2. **P2 — Provider-only save overstates the scope of success.** Image 27 immediately after step 27 shows “Settings saved” while the fixed footer simultaneously says “Unsaved changes across settings.” The action record says the toast followed saving only Beta provider; image 26 shows the General draft 12 survives, and the field assertion reports persisted max null. The broad toast can make a user believe the pending General change was committed. Say “Provider saved” or an equivalent precisely scoped outcome while retaining the global unsaved indicator and existing independent save behavior. Verify by editing General without Apply, saving a provider, and checking the provider receipt and unsaved General value remain unambiguous. This is a communication defect, not evidence of General being saved or lost.

3. **P2 — Management rows conceal the names needed to choose an edit/delete target.** Images 25, 27–28 and 35 show two long provider names truncated to nearly the same prefix; step 28 reports no full-name tooltip on hover. Image 29's model picker displays full provider identities, and image 36's editor header exposes Alpha, but neither is a direct identification cue on the management row before choosing Edit or Delete. Expose complete provider identity on the row or through a pointer- and keyboard-accessible detail; retain the real provider name and distinct action targets. Verify two same-prefix fake profiles can be reliably identified before invoking either action, in English and Chinese.

4. **P2 — Chinese Appearance contains untranslated functional choices.** Images 33–34 show Chinese section labels and explanations but the immediately actionable theme choices still read “System,” “Light,” “Dark” and contrast choices “Standard,” “High.” Preset names may be proper names, but these functional mode labels convey essential meanings and are not necessarily self-explanatory to a Chinese-only reader. Localize functional choices consistently, keeping preset identities where appropriate and preserving immediately applied behavior. Verify both light and dark Chinese, including accessible names; no conclusion about other pages or translation coverage.

5. **P3 — Dark secondary copy is visually faint.** Images 31–33 show subdued explanatory text and inactive navigation against dark surfaces, particularly the General interaction instructions in 32. The structure remains visible, but small low-luminance copy is a reading risk. Measure actual foreground/background contrast and inspect in normal use and high-contrast mode before adjusting semantic tokens; retain the clear labels, checkmarks and hierarchy. JPEG pixels are not a reliable conformance measurement, and this is not a WCAG failure claim.
