# Settings draft integrity review

Scope: independent static review of the uncommitted `SettingsView.tsx` and `settings-interaction.test.ts` diff against HEAD `bd27fafbb8db9894090d7f0ff88677e7dbb7fbe8`, after reading `AGENTS.md` and `apps/zenx/docs/ui-ux.md`. Did not edit source, run a full suite, or use native UI. Line numbers refer to the diff at review time. Another worker owns the test execution and source fixes.

## Findings

1. **P2, data integrity: unchanged model references override newer Host selections.** `SettingsView.tsx:1348–1359` retains `latest.defaultModel` and `latest.titleModel` whenever their targets still exist, irrespective of whether those fields differ from the captured `settings.profile`. For example, a provider edit commits, another client changes the default to a different still-existing model, and the committed-error refresh reads that newer Host profile. The rebase restores the old local default over the authoritative default, makes the draft dirty, and a subsequent Apply can overwrite the other client's change using the fresh revision. The same applies to title model and any successful provider response carrying an independently changed valid selection. Preserve a reference only if it is a genuine local edit relative to the appropriate baseline and is valid in the returned provider set; otherwise adopt the returned reference. Test both unchanged fields when the Host changes them, alongside an actual local edit, including a removed target.

2. **P2, invalid user input can be silently discarded by an independent update.** `SettingsView.tsx:1334–1345, 3975–3982, 4164–4182`: invalid raw maximum text exists only in GeneralPanel, while the profile retains its preceding valid value. With baseline 4, start a provider mutation, enter 0 while it is pending, then have its committed-error refresh return a Host profile with maximum 8 (e.g. a subsequent other-client edit). The rebase sees no local profile edit, adopts 8, and the effect replaces the visible 0 and clears the global invalid flag. This loses the unfinished local input and re-enables Apply. Preserve invalid raw text and validity across unrelated Host updates until the user explicitly corrects or discards it. Test that sequence with deferred provider completion and a changed Host maximum, and verify the raw text remains visible after reopening General and Apply stays disabled.

3. **P2, potential stale authority rollback on overlapping asynchronous reads.** `SettingsView.tsx:167–199, 1328–1347` unconditionally installs a provider result even if a newer Host result arrived in the meantime. While a provider mutation is pending, leave and return to Settings with a pristine draft, allowing activation's `settings.get()` to return revision 3; then resolve the older provider response carrying revision 2. The callback installs revision 2 and its provider list, and computes edits relative to the older render's captured profile. The UI can roll back a newer observed Host state and subsequent Apply may conflict (the Host revision check is expected to prevent a stale commit). Add a deferred-response regression, retaining monotonic authority and using the matching baseline when merging. This is a code-path assessment; ordering was not exercised natively in this review.

4. **P2, native input sanitization needs a targeted check.** `SettingsView.tsx:4152–4175` treats `event.currentTarget.value === ""` as deliberate clearing and sets `maxToolRounds` undefined. Chromium number inputs may expose an empty value plus `validity.badInput` for a partially typed number such as a lone minus or incomplete exponent. In that state the global invalid flag is cleared and an unrelated dirty change can allow Apply to save unlimited. Check `validity.badInput` separately from intentional deletion, and verify with real native typing because a jsdom value assignment is not sufficient evidence. This is an implementation risk grounded in browser number-input behavior, not a native reproduction performed in this review.

## Limits

The added tests cover a delayed provider success and committed-error retaining parsed General drafts, and a dirty draft plus `0` across navigation. I inspected but did not independently execute them. I did not verify platform-specific event behavior, full suite health, or every settings mutation. The findings above were sent to the lead as discovered.
