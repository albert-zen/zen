Independent review, 2026-11-09. No production edits, desktop actions, commits or pushes performed. No other review was read. Scores use the fixed 0–4 rubric; there is no overall score.

## Finding first

The pending scrollbar and larger running-send panel are visible improvements over the scope-matched originals. All three queue rows can be exposed, the 390px Chinese/dark panel is contained, and the recorded 200% keyboard states expose both the footer and the first alternative action. The native Subagents journey shows coherent child identity, explicit Idle/Archived states, a separate source action, and visible focus recovery.

No P1 visual failure is demonstrated by the accepted images. One P2 discoverability issue remains: a child can visibly read **Hidden** while still displayed in Information, beside an unrelated card-level **Hide**, without any resting label saying **sidebar**. Existing action tooltip/accessibility labeling is acknowledged, not assumed absent. Four smaller issues below are P3. There is no demonstrated new pending visual regression in the matched scope. This is not full-app acceptance.

## Five highest-impact findings

### 1. P2: Explain the scope of Hidden/Shown without consuming child-name width

- **Exact target:** A01/A03/A08 right-hand child control; A09 equivalent in the split popover. The section also has **Hide** at its upper right.
- **Trigger:** a new user opens Information before learning the switch's tooltip.
- **Consequence:** the visible child is labeled Hidden without saying where; presentation visibility can be confused with the child being hidden from this panel or disabled. This is discoverability friction, not evidence of incorrect persistence or inaccessible naming.
- **Compact change:** add one quiet **Sidebar** column heading above the right-aligned Hidden/Shown controls in the existing vertical interval below Side chat. Keep the current state labels, tooltip/accessibility labeling, Idle/Archived column and child-name widths. Do not widen each control or redesign the card.
- **Verification/falsifier:** at the approximately 340px card and roughly 416px allocation, no name-width regression or horizontal overflow; unprompted first-time users explain Hidden/Shown as sidebar-only visibility before hover. If the current control is consistently understood without prompting, downgrade this to P3.

### 2. P3: Two upward glyphs obscure two different queue operations

- **Exact target:** P02 queue-row action cluster, especially row 2: reorder-up chevron and promote-to-Steer arrow. Same ambiguity exists in B02/B15; not new.
- **Trigger:** choosing between reordering a queued message and applying it to the current turn.
- **Consequence:** users must inspect tooltip/focus names rather than recognizing the two operations at a glance. The screenshot does not prove their current labels or targets are missing.
- **Change/task:** verify the existing action tooltip and accessible-name distinction first; trial a more distinct steer glyph or a concise labeled action treatment if identification remains weak.
- **Verification:** first-time users choose reorder versus steer correctly at the tested density without trial activation; retain canonical actions, controls and current queue geometry.

### 3. P3: Clarify the menu's scroll boundary at 200%, not by shrinking it

- **Exact target:** P07 just below the pinned current-action summary: **Send each queued message in its own next turn** remains while **Each turn** is above the scrolled boundary. P08 shows Stop partly below the bottom boundary.
- **Trigger:** native 200% zoom, focus moving between footer and first alternative.
- **Consequence:** the menu remains keyboard reachable, but partial row fragments do not clearly advertise a single scrollable action area. This is not a claim that the clipped alternatives are unreachable.
- **Change:** keep the readable size and deliberate internal scroll; add a quiet persistent thumb/edge cue, or prevent a boundary from visually merging an orphan description with the pinned summary.
- **Verification:** capture both focus positions again, with a clear overflow cue and the focused control fully visible; pointer scrolling also exposes every action and footer. Do not force all actions into the viewport by reducing type or hit targets.

### 4. P3: Keep complete archived-child identity available

- **Exact target:** A08's archived child title displays **Archived reviewer · nati…**, beside its intact Archived status.
- **Trigger:** several siblings with similar prefixes, or a long name whose useful distinction is at its end.
- **Consequence:** selecting the intended child may require exploration. Current full-name tooltip/accessibility behavior is N/O; no absence is asserted.
- **Change/task:** verify complete-name disclosure on pointer and keyboard first. If unavailable, add it; consider a bounded second line only if it does not displace lifecycle/visibility or widen the card.
- **Verification:** long, common-prefix sibling names are distinguishable without opening them, at both Information widths, and Archived stays visible.

### 5. P3: Make canonical source navigation look slightly more actionable

- **Exact target:** A05/A08 **From QA reviewer · native child**, immediately above the received report.
- **Trigger:** users want to inspect the sender rather than merely read the report.
- **Consequence:** this small gray row resembles static metadata, while irrelevant raw-path links are much stronger. The recorded successful activation proves a route exists, not that it is obvious.
- **Change/task:** test discovery first. If missed, add one compact directional/navigation cue or similarly restrained affordance while preserving the From identity and message-source icon. Inspect current hover/focus treatment before changing it.
- **Verification:** users locate the sender unaided; keyboard focus visibly identifies the action; activation still opens the canonical child and never sends or follows a target inferred from body text.

## Three strengths to preserve

1. **One bounded pending tray with an honest overflow cue.** P01 makes undisplayed rows discoverable at rest; P02 exposes all three queue rows without adding tabs, a second nested scroll region, or a “view all” detour.
2. **Larger command text without changing the send model.** P03/P06 retain a single current action, explicit alternatives and a distinct preference footer. P04/P05 and P07/P08 preserve useful focus evidence rather than trading readability for an all-at-once layout.
3. **Native child identity and local ownership stay coherent.** A04's companion, A05's provenance, A06's main breadcrumb and A07's empty child Information are different roles, not copies of one misleading card. Idle, Archived and sidebar visibility are separate facts.

## Prioritized next iteration and limits on change

1. Address or task-test the single **Sidebar** scope label, preserving current width and name readability.
2. Verify a subtle 200% menu overflow cue and existing queue/source/full-name affordances before making further visual changes. These P3 issues do not justify a shell or Information redesign.
3. Rebuild and recapture the exact final source if using this review for acceptance. Run native behavior checks for any changed callbacks; the current Information build explicitly predates the later fix.

Do **not** split the pending tray, collapse truthful pending/unknown states into transcript, change queue/steer/send behavior, remove the one-click primary orb, shrink text/targets to avoid zoom scrolling, replace keyboard focus with selected-state tint, remove canonical provenance, or add a permanent mobile/overflow control contrary to the product contract. Do not copy T3/Linear styling or erase useful semantic color just to resemble the references.
