# Independent baseline UI review

## Scope and limits

Native Electron actual-app screenshot pack, commit d7f93b83f54ba873b61f19bd72ac3a6f6010aa4a, 1188×848, images 01–09, manifest captured 2026-11-09. I inspected all nine saved PNGs and the supplied T3 marketing image, historic Linear redesign comparison, and Geist documentation image. These references are illustrative published images, not live app audits or behavior specifications. QA provider and echo content are synthetic; do not interpret the echo as production model behavior. This is the first review of this frozen baseline, not a paired or blind comparison. Screenshot pixels cannot establish focus order, actual control size, contrast ratios, scrolling, delivery, persistence, reduced motion or responsive behavior. Pending, Fork, streaming, failure, narrow viewport and interactive states are not shown. Product rules in apps/zenx/docs/ui-ux.md remain authoritative.

## Five highest-impact findings

1. **P2 — Persistent PAW promotion competes with current work.** Target sidebar card and blue CTA, 01–09. Trigger: existing conversation or settings open. Consequence: a setup invitation retains primary-action visual weight regardless of context. Change: compact or visually demote while retaining an explicit entry. Verify side-by-side screenshots and first-task findability, including setup discovery.
2. **P2 — Account setup lacks a direct visible route.** Target Account > Connect an account, 03. Trigger: not configured. Consequence: user must infer and navigate to Models & provider from explanatory text. Change: add a contextual navigation control to the exact existing destination; verify keyboard and pointer navigation and return path without changing sign-in semantics.
3. **P2 — Small muted secondary labels compromise scanability.** Target sidebar metadata, appearance preset descriptors and dark secondary controls, 01–09, especially 05/07. Trigger: reading at actual capture scale or in dark theme. Consequence: metadata and selection distinctions take more effort to parse. Change: raise minimum type size and test token contrast, preserving hierarchy; verify rendered text and measured contrast in both themes, including zoom.
4. **P2 — Information panel lacks visible purpose/content.** Target panel in 09. Trigger: opening information. Consequence: an almost empty floating card with Close information and Customize offers little context for why it exists. Change: add a concise heading and truthful empty-state explanation or render real available information, subject to existing product rules. Verify empty, populated, unavailable and customizable states without implying unavailable data.
5. **P2 — Footer occlusion and narrow layout require explicit verification.** Target General settings bottom content, 06. Trigger: content extends under fixed footer. Consequence: visible text is cut off in this frame and discoverability of the rest is uncertain, not proof of a broken scroll. Change: ensure adequate scroll padding and test reachability; verify last controls at 1188×848 and 390×600 with keyboard and pointer.

## Strengths to preserve

- Current thread and settings section have recognizable selection treatment, and labeled settings categories support scanning (02–06).
- Chat body preserves useful text hierarchy, lists, quotes and code treatment; composer stays visually separate (02/08).
- Both themes carry the same component language, and state text such as Not configured and Blocked avoids color-only interpretation (03, 06–08).

## Next iteration and guardrails

First improve sidebar promotion priority, account setup path, secondary text legibility and information empty-state clarity; verify fixed-footer reachability and narrow composition. Then capture interactive pending/Fork, errors, saving, keyboard focus and assistive technology states and measure color contrast. Do not replace authoritative pending/accepted/uncertain semantics with inferred states, change scroll behavior or message delivery, flatten useful distinctions, clone reference products, or claim responsive/accessibility success from these static screenshots.
