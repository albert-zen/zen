## Five highest-impact actionable findings

These are the highest-impact opportunities supported by this pack, all **P3**. No pictured state establishes a P1 blocker or a P2 task failure/material friction claim.

1. **Dark unselected text can resemble unavailable controls.** Exact target: C03 System/Light labels, unselected Cobalt/Ember tiles, and secondary helper text. Trigger: Dark + Standard. Consequence: weaker reading and weaker active-versus-disabled affordance. Verification: measure rendered contrast and compare active-unselected/disabled/focus states at native size; increase secondary emphasis only where necessary. Do not remove the useful difference between primary and supporting text.
2. **Fork provenance competes with pathname metadata.** Target: C01's header second line, especially “Copied from Fork source · synthetic QA.” Trigger: opening a fork. Consequence: a user seeking the original must scan a long, visually uniform metadata line. Verification: separate or strengthen the explicit source action, then show the same source navigation outcome and no new header overflow. Retain the path and canonical boundary semantics.
3. **Compact settings navigation delays the current controls.** Target: C05's four-row settings grid above Appearance. Trigger: 906×724 initial view. Consequence: contrast and reset require scrolling, although the content is correctly reachable. Verification: reduce the grid's initial vertical cost or provide a labeled compact chooser; all ten sections and selection must remain discoverable, with the card and labels contained. Scrolling itself is not a defect.
4. **Saved presets need explanation near the decision.** Target: C04–C07 Light preset/Dark preset headings and two checked Graphite tiles. Trigger: Light is selected while both mode-specific saved presets display a check. Consequence: a new user must rely on a small footer sentence to understand that these are independent stored preferences, not two current themes. Verification: place short, accurate saved-preset context near the groups and confirm both checked states remain clearly associated with their respective group. Do not remove either saved selection.
5. **“Local” scope is underexplained.** Target: C03–C07 upper-right card label. Trigger: configuring Appearance. Consequence: “Local” alone does not explain the boundary between device/account/project settings. Verification: first establish actual scope, then use a concise explicit label or accessible explanation that fits at both widths. Do not invent synchronization behavior.

## Paired conclusions and falsification

Only F0↔C01 and A0↔C03 are matched comparisons. C04–C07 establish additional candidate coverage, not comparative wins over unseen earlier equivalents.

- **Hierarchy/grouping:** C01 improves on F0 by adding the visible copied-history separator. Appearance grouping is essentially unchanged. Preference would be falsified if the boundary were placed somewhere other than the canonical inherited/new-history split; the supplied manifest and displayed continuation support its placement here.
- **Color semantics:** C03 improves on A0 because selected Dark and Standard now have checkmarks. The faint unselected dark text remains. Preference would be falsified by checks failing to track selection or appearing on unavailable/unselected choices.
- **Materials:** broadly unchanged between A0 and C03 and between F0 and C01, apart from the purposeful divider/check additions. No unsupported material-system win is claimed.
- **Readability/density:** C03 improves the cramped contrast-choice presentation by allocating space for Standard plus a check. Other typography remains similar. C01 adds boundary explanation but does not fix the small source/path line. A matched long-label/zoom test could falsify the fitting claim outside the shown labels.
- **Attention:** C01 better directs attention to the transition from inherited to new history; C03's selection checks add useful information with little extra visual load. Sidebar/onboarding competition remains. No global attention improvement is established.
- **Navigation:** no material visual change to the source link or Settings navigation in matched screenshots. C02 supports correct source context in this checkpoint, not a new navigation win. Compact reflow has no matched comparator in this review.
- **Feedback:** C03 improves visible selection feedback. This does not establish persistence, delivery, failure handling, or input timing improvements.
- **Composition/responsiveness:** stable full-size geometry is broadly preserved. The candidate's compact fit is supported directly, but comparative responsiveness is N/O without an equivalent older compact capture. A native 906×724 capture showing any selected label/check crossing its control would falsify the current containment conclusion.
- **Accessibility/input robustness:** no comparative score. Non-color cues improve; input and assistive technology remain untested.
- **Cross-surface/product fit:** the changes preserve visible existing semantics. No new mismatch or regression is established in matched states. This is narrower than saying none exists elsewhere.

## Prioritized next iteration

1. Verify Dark/Standard secondary text and active/disabled distinction with measured tokens plus focused input evidence; adjust only demonstrated weaknesses.
2. Make Fork source provenance and Appearance scope/preset explanations easier to locate, retaining the current product semantics.
3. Reduce compact navigation's initial height and re-capture both initial and scrolled states, including long labels/zoom. Test keyboard, selected-state accessibility, persistence, and reset separately rather than inferring them from these images.

**Do not change:** canonical Fork placement/source navigation, source-only versus branch-only content, existing non-color checks, stable selected-control widths, meaningful accent swatches, the theme/preview material distinctions, or deliberate vertical scrolling. Do not hide uncertainty or failures merely to create a quieter screen, replace real native evidence with mockups, or claim live-provider/streaming/accessibility success from these synthetic screenshots.
