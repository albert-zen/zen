## Findings

1. **[P2] A create error removes the healthy empty entry and breaks return focus.** `bundled-automation-ui.tsx:2949–2953` uses generic `error` as though it were a Rooms read failure. Reproduce with a healthy empty Rooms list and an available member Thread: open the new empty-state New Room button, submit valid fields, and have the create command reject or return an unknown outcome. The existing create path records a mutation error at lines 2473–2481 and refreshes the list; even if that refresh succeeds and confirms it remains empty, the generic error is not cleared by successful list polling (lines 2188–2189). The empty-state button is unmounted and the background page misleadingly says Rooms are unavailable. Closing or pressing Escape then calls `.focus()` on its detached invoker (lines 2225–2236), so focus does not return as promised, and the inline entry remains missing until another action clears the generic error or the component/route resets. Other pre-existing navigation creation routes may still be available; this is not a claim that all creation is blocked. The same focus loss can occur if a Rooms refresh fails while the dialog is open. Keep mutation diagnostics separate from the list-health decision and provide a live fallback focus target if the entry can disappear. The new happy-path test covers Close/Escape without an intervening error, not this sequence.

2. **[P2] A stale failed refresh can overwrite a newer successful result.** `bundled-automation-ui.tsx:2200–2208` assigns `roomsReadError` in outer rejection handlers without the request's sequence or view epoch check. Successful results are guarded by the sequence/epoch checks around lines 2051–2055 and 2074, and a successful refresh clears the error at 2188. Reproduce by starting list read A, starting a later read B (the 3-second polling interval or an SDK change can overlap reads), resolving B successfully with an empty list, then rejecting A. A's catch executes last and changes the healthy empty page to the unavailable alert, removing New Room, despite B being the newer authoritative read. It remains wrong until a subsequent successful read clears the error. Request freshness should fence failures as well as successes. The new failure/recovery test resolves the failure before success; it does not exercise reversed completion order. The overlapping polling mechanism and existing sequence mechanism predate this diff; the new error state and empty-state branch make this stale failure visible as the new regression.
