## 可观察的 U/V 差异与未解决成本

- 三组匹配图中，V 的 Built in 与状态徽章明显变大；U 的徽章更紧凑。V 降低状态识读成本，但更接近名称的视觉权重，并增加行高。不能仅据此证明任务完成更快。
- All 库存中，U 的 Install 为蓝色实心，V 为中性描边。U 更容易首先找到安装入口；多个按钮重复时会压过库存信息。V 更适合扫名称和状态，但安装动作的第一眼显著性下降。
- Installed 两图均用中性 Disable 和 More actions，主要差别仍是徽章与行高。单条结果时，V 的额外高度几乎不增加滚动成本；不能外推长列表。
- 下部 All 均以 ZenX self-control 为末项。U 上缘有上一行碎片，V 以 Computer 开始，属底部锚定、行高不同带来的可见差异，不能称 V 删除了内容或滚动错误。
- Fleet 行较亮、滚动条/悬停状态与捕获时机可能不同，不能归因于设计变化或当作键盘焦点。
- 两者均保留较小且灰的说明、双侧栏、重复详情入口及多层细边框。V 改善状态字号并未解决所有信息密度或对比问题。
