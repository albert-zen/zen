## Five highest-impact findings

1. **P2: Information panel opens without explaining its content or absence.** Target: 09-information.png, right-side rounded surface, approximately x836–1175/y100–214 and the reserved column below. Trigger: information panel open with this fixture state. Consequence: the conversation and Composer lose substantial width, but the new surface provides only Close information and Customize, leaving purpose and emptiness ambiguous. Change: add an honest compact empty-state heading/explanation and meaningful existing customization action; do not invent live information or auto-close meaningful attention. Verification: same fixture shows an understandable empty state, explicit close, and unobstructed conversation; populated/asking cards remain separately visible and cannot be hidden by cosmetic customization.

2. **P2: Persistent onboarding competes with current work.** Target: 01–09, PAW card at x16–238/y266–396. Trigger: unconfigured PAW while navigating chat/settings. Consequence: the saturated setup CTA and multi-line card repeatedly occupy scarce sidebar space, visually outranking thread and project navigation, including while users are completing unrelated setup. Change: retain clear PAW access but reduce repeat exposure to a compact entry after the initial encounter or an explicit dismissal; respect the existing Later behavior and product ownership. Verification: selected thread, project labels and more thread rows are easier to scan, setup stays discoverable, and attention/status capsules are not displaced or weakened.

3. **P2: Account setup instruction is not an obvious action.** Target: 03-settings-account.png, OpenAI subscription card. Trigger: account Not configured. Consequence: user must interpret prose, locate Models & provider and repeat navigation to reach setup; Connect an account looks like an inert section title. Change: a labeled button/link that navigates to the actual existing provider setup path, without introducing a separate subscription or sign-in model. Verification: activation leads to the intended surface with keyboard focus handled, and no unintended external auth or save occurs merely by navigating.

4. **P2: Metadata type hierarchy becomes too small in dense controls.** Target: 04 provider-row badges and 05/07 preset/accent subtitles; repeated sidebar source lines in all frames. Trigger: scanning providers or choosing appearance. Consequence: users must inspect tiny labels to distinguish configuration/status details, while repeated sidebar source text consumes vertical space yet does not distinguish this fixture's rows. Change: establish a readable metadata tier, improve badge text size/padding, and reduce redundant visual weight without removing agent/source provenance. Verification: same viewport and labels remain visible without truncation or action collision; measured contrast and zoom tests pass separately. Do not mistake fixture sameness for proof all source labels are redundant in production.

5. **P2: Selected option semantics need more than subtle border/fill differences.** Target: 05/07 theme, light/dark preset and accent option groups. Trigger: determining current appearance choices, particularly dark theme. Consequence: multiple groups use similar outlines and modest tonal shifts, imposing extra visual comparison and providing limited screenshot-visible non-color selection indication. Change: use one compact selected check/mark consistently on choice cards while preserving semantic color swatches and theme labels. Verification: a grayscale/static screenshot still identifies every selected option; keyboard focus is visually distinguishable from selection, accessible checked/pressed state is verified, and controls remain usable at narrow width.

No evidenced P1 task blocker. Issues involving unseen failure, pending or narrow states are verification tasks, not invented defects.

## Three strengths to preserve

- Clear conversation reading structure: 02/08 keep paragraph, heading, bullets, decision emphasis, quote and code distinctions, with work-duration metadata subordinate and a stable bottom Composer.
- Coherent theme translation: 05/07 and 02/08 preserve component geometry and hierarchy rather than making dark mode a different application. Semantic accent and destructive styling remain useful.
- Honest resting-state copy: 03 says Not configured; 06 says Blocked and explains consequential foreground access; 05/07 explicitly state immediate application. These labels communicate facts instead of using color alone.

## Prioritized next iteration and constraints

1. Fix the account setup route affordance and empty information presentation with shared existing components.
2. Reduce repeat PAW promotion weight while preserving its navigation, onboarding opportunity and explicit dismissal semantics.
3. Normalize metadata type tiers and add consistent non-color selected markers to appearance choices; measure contrast rather than guessing.
4. Expand immutable evidence before deeper redesign: narrow 390×600, focused navigation, long labels, General bottom scroll, populated information, pending/approval/error/draft together, sending through authoritative acceptance, failed/uncertain outcomes, Fork pending/error, and reader-upscroll/Back to live.

Must not change: pending-message admission versus model consumption distinctions; exact-target queue/recall identities and uncertainty handling; no automatic resend or inferred success; bounded unified Steer/Queue shelf; original draft/attachment ownership; existing Fork durable boundary and no automatic duplicate creation; thread/project/Room ownership and ordering; scroll position while reading history and live-follow/Back to live contract; Composer overlay and bottom virtual clearance; keyboard reachability and reduced-motion behavior. Do not hide overflow to make a cleaner screenshot, change runtime/product behavior to mimic a reference, remove truthful source/status information, or award a calm appearance for hiding failure. Screenshot 06's below-fold content and all small visible icons require behavioral/geometry verification, not unsupported clipping or target-size claims.

This is an unpaired baseline review. Candidate preference, regressions and paired falsification are N/O until a candidate pack exists.
