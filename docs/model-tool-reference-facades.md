# Typed compact model tool facades

This is a fresh rebuild on public `81ff10d5`, not a recovery claim for vanished unpublished commits. The child capability boundary projects explicitly known first-party schemas, input fields and result fields. Native/UI contracts and backend authorization remain authoritative. There is no arbitrary string rewriting: user text, errors, code, paths, hashes, URLs and authored custom identifiers remain literal.

## Binding and provenance

- `s1` is a selected source generated by the Context compiler; only explicit local history reads may consume it, never mutations.
- `r1` is a typed tool reference in its receiving Thread. Internal metadata retains the exact original identity/authority tuple. A ref is neither permission nor a freshness renewal.
- The registry is a disposable cache of existing canonical provenance. Every used/emitted binding repeats in each result, so a failed allocating result or out-of-order commit cannot orphan an otherwise visible cached ref. Inherited aliases reserve numbers but cannot grant their parent's authority.
- WeakMap-backed trusted attachments distinguish Host provenance from untrusted tool JSON. Mutation of the attached metadata invalidates its trust. Shape validation alone never authenticates metadata.
- Computer observations/captures and immutable configuration snapshots are bound to the capability-instance epoch. Provider replacement/restart cannot revive those references. Immutable Trace-result references are owner-scoped evidence, not execution authority, and intentionally remain readable after restart.

## Publication budget and evidence

Each capability-result producer reserves at most 4,096 distinct emitted bindings and 1 MiB of their exact serialized array before exposing the compact result. Existing consumed bindings are never dropped by that publication budget. Aggregation retains every already-issued binding; the existing runner's child-count limit is separate, and there is no late aggregate rejection that loses visible references.

If output projection exceeds the budget after dispatch, the result retains its original exit code and reports `projection: "projection_unavailable"` separately from known typed outcome facts. If no reliable outcome fact exists it says `unclassified`, never “not executed”. Partial output refs and raw routing-envelope dumps are not exposed, and no mutation is retried.

Before ordinary projection, a durable raw Trace capture plus a trusted configured `trace_read` runtime permits reserving one exact inspection ref in existing provenance: namespace `trace`, kind `tool-result`, value `{ locator, tool: "trace_read" }`. A budget receipt retains its input refs plus this inspection ref. If durable evidence or the reader is unavailable, it does not claim model-inspectability. Core/Trace owns actual reader registration, record/call/owner validation and durable recovery integration; a synthetic sink test is not proof of that integration.

## Verification and explicit exclusions

Synthetic tests exercise the real capability bridge and native product services: same-label identities, parallel stale observations, original-target immutable cursor continuation, stale captures, revoked permission, fork/provider/restart retirement, interleaved CAS, live sidebar membership, preserved foreign tab descriptors, literal UUIDs, failed/unknown history and delivery, selected-source read-only scope, root-only metadata filtering, and known/unclassified budget receipts. Existing native backend CI remains required; no real desktop action or paid model call is part of these tests. Source-mode native suites may fall back from an unavailable compiled Worker; actual nested `run_code` crash/yield/recovery acceptance is Core-owned.

Not covered by this slice:

- Fleet device/catalog/execution/task-handle projection. Routing may intercept before the capability facade; deviceKey, endpoint/workspace, process epoch, tool generation and qualified status handles must remain one exact authority tuple. Current remote device/workspace fields cannot be claimed fully compact or fully fenced by this slice.
- File-editor read/write baseline guards and renderer layout. Sidebar presentation does not read, write, save or discard file contents.

Plugin/panel names, semantic model names, paths/URLs and user-authored custom/note identifiers remain literal deliberately. This is not a universal annotation or redaction framework, and creates no fourth durable coordination/reference store.

## Browser boundary

Browser projection captures the native result before compact publication, including failure and completed-action/follow-up-observation distinctions. A cursor binds the immutable original session/tab and never recaptures or renews freshness. Generated native node, document, session and connection envelopes are not model prose; user text, page content, URLs, errors and artifact paths remain literal. The model uses full bounded first pages rather than a hidden retained diff baseline.

Approval scopes and resource claims resolve exactly the same compact connection/target before execution. The captured catalog generation is checked again by the existing native connection registry. A private branded sideband carries the exact existing product target identity separately from native tab IDs through trusted Host IPC and bundled/profile adapters. Native ordered dispatch checks owner, session epoch and product target identity without creating a session during lookup. New sidebar Browser descriptors use this exact target and the current native admission callback; existing sidebar descriptors retain their original semantics. This introduces no durable alias/routing store and never replays unknown effects.
