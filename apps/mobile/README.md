# ZenX Android (draft isolated Host integration)

Independent Expo/React Native Android client. The built-in demo device is explicitly a fixture; separately added and paired Host IDs use the isolated CLI TLS service (not the daily desktop Host). Android emulator/device pairing remains unverified; Node TLS interoperability is not Android device evidence. No Provider key, Agent runtime or canonical journal on device. Desktop stays Electron.

## Local

From `apps/mobile`: `npm ci && npm test && npm run typecheck`; with a local JDK 17, Android SDK/platform tools/build tools and accepted Android licenses, run `npm run prebuild`, then `npm run android` (dev client; not Expo Go). For a self-contained debug APK run `cd android && ./gradlew assembleDebug`; output `android/app/build/outputs/apk/debug/app-debug.apk`. `android/` is generated and ignored. The built-in demo remains fixture-only inside the APK; a remote Host requires pairing and OS-trusted TLS. No EAS login required.

The Host contract at `artifacts/inbox-dispatch-20260924/remote-host/CONTRACT.md` is owned by the other line. Transport integration must use its actual authentication, read/subscribe and command acknowledgements; do not infer success from HTTP dispatch or transport timeouts. Switching devices/workspaces cancels old subscriptions and ignores stale responses; an existing thread's cwd is never mutated. The primary-device preference and added addresses are local metadata; only a successful HTTPS pair grants a host-bound credential in Android SecureStore. Unpaired addresses cannot show fixture threads.

## Remote integration (stacked on Host PR #212)

Development Host is an **isolated CLI fake provider**, not the daily desktop app. Enter its Host ID and HTTPS origin; pair using the fresh one-use code from its protected file. The Android app checks OS TLS trust, pairs over HTTPS `/pair`, keeps the device credential in Android SecureStore, and verifies `zen/remote/hello` identity before exposing workspaces/threads. No fallback to HTTP, no TLS bypass, no credential in URL. Grants expire when the isolated Host process restarts; re-pair explicitly. `src/remote-core.ts` uses the one shared native contract at `src/protocol/native/remote-wire.ts` through Metro watchFolders; no duplicate wire package.

`npm run test:host` (after `npm ci` at repo root) runs an ephemeral local CA-trusted TLS Host with two clients and fake provider; no user Host, listener or paid account. Host PR #212 R1/R2/R3 did **not** pass independent review. This stacked branch now includes the Host owner's final local fix candidate `a1baf777` (a separate cherry-pick); native v1 shape/version remain unchanged. The final fix adds a reset on lost live scope/read gap and isolates page busy by generation. Host's three independent-review rounds are exhausted; **this last candidate has not had another independent Host review** and must not be called security-approved. The mobile client discards partial pages on reset/epoch/gap or stale cursor, performs at most one automatic fresh resume on stale cursor, and blocks commands until a complete fresh snapshot. Mobile unit coverage includes >2 MiB fragmented text, reset during paged recovery, denied scope/regrant, old callback generation and unknown send delivery. A local CA-trusted fake TLS Host with two Node clients additionally tests live scope loss/reset/regrant; no daily Host, actual Android emulator screenshot, or Android device TLS connection has been measured. Do not claim production approval.

## R1 mobile review fixes (same draft PR #213)

Independent mobile/base+integration R1 of `929fd6b` was **NOT PASS** (B1–B3); see `artifacts/inbox-dispatch-20260924/review-android-r1/REVIEW.md`. The follow-up client keeps the Host owner final candidate and native v1 wire unchanged. On explicit Host close 4003, discard public Items, Turn IDs, buffered recovery and page view, mark the grant revoked until a fresh pair; on an ordinary disconnect clear the public view too, but do not invalidate a still-usable grant. An in-flight send with unknown delivery stays fenced to its original Host/workspace/Thread despite clearing the view; completed canonical read after explicit reconnect permits an informed new submission. This is no offline history feature and cannot retract text already seen.

Thread and operation identities fence async reads/acks/rejections within one workspace. A bounded in-memory per-Thread send fence is not a durable log or a second canonical source; it neither resends nor invents terminal outcomes. App handlers clear draft on Thread switch; late pair results cannot update another Host UI, late send acknowledgements clear only the unchanged original draft. Send/stop acknowledgements identify the admitted/requested Turn, not its final result: the page separately shows the Host's canonical `inProgress`/`completed`/`failed`/`interrupted` lifecycle from live events and recovery, without tools or error text. Remote Thread summary `idle` is not success. Tests do not substitute for on-device UI verification.

**Remaining liveness limit:** A page request that never responds can still block the next Thread's recovery on that connection; requests have no per-RPC deadline. Manual Host reconnect closes the old socket. Do not claim instant B recovery or unknown-delivery resolution. Device environment has user-local JDK17/SDK/adb, but at this writing no emulator/image/AVD and the shared disk is ~99% full; this owner does not install or occupy an AVD. Actual Android TLS/screenshot still needs independent device QA. No daily Host, real Provider, merge, or Host R4.
