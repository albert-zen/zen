# ZenX Android Fleet client

Independent Expo/React Native Android client for the native, authenticated Fleet Host protocol. Fleet manages device addresses/names and SecureStore pairing credentials; Threads and Rooms show disposable Host projections. The built-in demo device is explicitly fixture-only. No Provider key, Agent runtime, scheduler or canonical journal lives on the phone. Desktop stays Electron. Android emulator/device pairing remains unverified; Node TLS interoperability is not Android device evidence.

## Local

From `apps/mobile`: `npm ci && npm test && npm run typecheck` (use `node --import tsx --test test/*.test.mjs test/*.test.ts` when the `tsx` executable is unavailable); with a local JDK 17, Android SDK/platform tools/build tools and accepted Android licenses, run `npm run prebuild`, then `npm run android` (dev client; not Expo Go). For a self-contained debug APK run `cd android && ./gradlew assembleDebug`; output `android/app/build/outputs/apk/debug/app-debug.apk`. `android/` is generated and ignored. The built-in demo remains fixture-only inside the APK; a remote Host requires pairing and OS-trusted TLS. No EAS login required.

The Host contract at `artifacts/inbox-dispatch-20260924/remote-host/CONTRACT.md` is owned by the other line. Transport integration must use its actual authentication, read/subscribe and command acknowledgements; do not infer success from HTTP dispatch or transport timeouts. Switching devices/workspaces cancels old subscriptions and ignores stale responses; an existing thread's cwd is never mutated. The primary-device preference and added addresses are local metadata; only a successful HTTPS pair grants a host-bound credential in Android SecureStore. Unpaired addresses cannot show fixture threads.

## Remote integration (stacked on Host PR #212)

Development Host is an **isolated CLI fake provider**, not the daily desktop app. Enter its Host ID and HTTPS origin; pair using the fresh one-use code from its protected file. The Android app checks OS TLS trust, pairs over HTTPS `/pair`, keeps the device credential in Android SecureStore, and verifies `zen/remote/hello` identity before exposing workspaces/threads. No fallback to HTTP, no TLS bypass, no credential in URL. Persistent Host grant storage preserves explicitly paired credentials across ordinary Host restarts; revoked/removed grants require fresh pairing. Transport disconnects alone never mean the grant was revoked. `src/remote-core.ts` uses the one shared native contract at `src/protocol/native/remote-wire.ts` through Metro watchFolders; no duplicate wire package.

`npm run test:host` (after `npm ci` at repo root) runs an ephemeral local CA-trusted TLS Host with two clients and fake provider; no user Host, listener or paid account. Host PR #212 R1/R2/R3 did **not** pass independent review. This stacked branch now includes the Host owner's final local fix candidate `a1baf777` (a separate cherry-pick); native v1 shape/version remain unchanged. The final fix adds a reset on lost live scope/read gap and isolates page busy by generation. Host's three independent-review rounds are exhausted; **this last candidate has not had another independent Host review** and must not be called security-approved. The mobile client discards partial pages on reset/epoch/gap or stale cursor, performs at most one automatic fresh resume on stale cursor, and blocks commands until a complete fresh snapshot. Mobile unit coverage includes >2 MiB fragmented text, reset during paged recovery, denied scope/regrant, old callback generation and unknown send delivery. A local CA-trusted fake TLS Host with two Node clients additionally tests live scope loss/reset/regrant; no daily Host, actual Android emulator screenshot, or Android device TLS connection has been measured. Do not claim production approval.

## Fleet and assistant Rooms

- Fleet adds HTTPS origin + Host ID + optional device name, persists rename/default selection, and asks before removing an address or forgetting its pairing. Forget affects this phone's saved credential, not the Host's grant or running work. The Host's Fleet hosting screen controls actual revocation.
- Device labels distinguish saved pairing from a verified live connection. An unselected paired device is disconnected from this client; no offline/online state is guessed for it. Invalid/changed origins require pairing again. Origins containing credentials, paths, queries, fragments or plaintext HTTP are rejected.
- Switching device/workspace fences old requests, subscriptions, receipts and drafts. Thread operations carry the selected Host/workspace, create opens the exact admitted Thread, and new-thread model/effort choices use the Host's catalog. Existing Thread model/workspace is not mutated. Busy sends may be accepted as queued input; Host canonical events supply the actual lifecycle.
- Hosts advertising `rooms` expose only Rooms authorized by the device grant. The phone reads deliberate human/agent/system Room posts, posts human input, refreshes on native Room notifications, and polls every four seconds only while the Room pane is open. Turn completion does not manufacture a Room reply. Room posts capture the read operation epoch in their exact client identity; an unknown receipt never auto-replays.
- A configured HTTPS relay address uses the same wire protocol: `x-zen-host-id` routes pairing and WebSocket upgrade to the exact Host. Bearer authentication remains only in the header, never the URL. No additional mobile runtime or journal is introduced.

The local fake-only tests cover multi-Host isolation, stale old-page callbacks, pairing/forget races, invalid origins, bounded hung RPCs, queued acknowledgements, scoped Rooms, interrupted reads, equal newly composed drafts and unknown-delivery fences. The CA-trusted TLS integration validates Host identity, canonical create/read/send/events, a second client and revocation. These are Node checks, not on-device UI/TLS validation or production security approval.
