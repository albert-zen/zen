# Application-current-focus keyboard UI

Real production ComputerThreadPanel and PluginAccessReview, rendered at source `bd99e55e1af55c77a15e46c98857b6257f893018`. SOURCE.json records the bundled source hashes and eight desktop/narrow, light/dark English/Chinese captures. All were visually checked; the permission review is fully visible and the app activity has no window image or action pointer.

Host data is synthetic: an Example Notes application activity and a locked native macOS readiness snapshot with existing permissions. No native window, input, real profile or OS permission is connected to this renderer fixture. These images verify the displayed scope and independent app permission, not actual keyboard effect or locked execution.

The app keyboard activity names the application current focus and allows internal focus changes. It does not claim the original window or control. This source includes the final application-scoped ordering policy and existing harness Trace integration. The target application may reorder its own windows behind the foreground application; external window identity/order and global foreground/pointer checks remain in force. Native application effects and cancellation are validated separately.
